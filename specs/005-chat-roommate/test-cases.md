# Test cases: ติดต่อ/แชทกับรูมเมท
อ้างอิง: spec.md SPEC-CHAT-005 Draft v6 | ปรับล่าสุด: 2569-11-14 (หลังทีมตอบ Q-07, Q-09, Q-10, Q-12)

คนออกแบบตารางนี้ AI เขียนโค้ด test ตามตารางด้วยคำสั่ง /testcases
- สถานะ: ร่าง (เสนอแล้ว ยังไม่มีใครตรวจ) / ใช้ได้ (ทีมตรวจแล้ว) / รอ Q-xx (ต้องรอคำตอบใน spec ก่อน)
- test ที่มาจากตารางนี้ ห้ามแก้ให้ผ่าน ถ้าไม่ผ่าน ต้องหาว่าโค้ดผิด หรือ AC ผิด (ถ้า AC ผิด แก้ spec ก่อน)
- ตรวจด้วย: pytest = test อัตโนมัติฝั่ง Backend, vitest (หน้าจอ) = test อัตโนมัติฝั่ง Frontend, คน = ทดสอบเอง (manual)
- ชื่อ test ในคอลัมน์ "ชื่อ test" เป็นชื่อตาม TC; test ที่เขียนไว้แล้วในโค้ดตั้งชื่อตาม AC (`test_AC_CHAT_xx_...`) จึงต้องดูตารางจับคู่ TC ↔ test จริงใน rtm.md ส่วน B ก่อนสร้าง test ซ้ำ
- ทุกแถวยังเป็น "ร่าง" หรือ "รอ Q-xx" เพราะทีมยังไม่ได้ตรวจ; เปลี่ยนเป็น "ใช้ได้" ได้เมื่อทีมอ่านแล้วเห็นด้วยเท่านั้น
- "ทางผิด" ในที่นี้คือกรณีที่ Given/When ผิดหรือไม่ครบเงื่อนไขของ AC หลัก; ถ้าเงื่อนไขนั้นเกิดไม่ได้ในระบบจริง (เช่น ส่งข้อความโดยไม่มีหน้าต่างแชทเปิด) ไม่นับเป็น TC และบันทึกไว้ในหมายเหตุท้ายไฟล์

## หมายเหตุ: กรณีที่ไม่นับเป็น TC (บันทึกไว้เพื่อให้ตรวจย้อนได้)
- ส่งข้อความ/ไฟล์ "โดยไม่มีหน้าต่างแชทเปิด" (TC เดิม TC-CHAT-02-3, 02C-4, 02A-3, 02B-3): เกิดไม่ได้ใน UI ฝั่งการใช้งานจริง; ส่วนที่ตรวจได้คือฝั่ง API ผู้ใช้ที่ไม่ใช่สมาชิกส่งไม่ได้ → ครอบคลุมโดย TC-CHAT-02-3 ใหม่
- AC-CHAT-09 กรณี "ผู้ทดสอบเคยใช้แชท" และ "ผู้ทดสอบไม่ครบ 5 คน" (TC เดิม TC-CHAT-09-4, 09-5): ไม่ตรงเงื่อนไข Given จึงไม่ใช่ test case แต่เป็นเงื่อนไขการคัดผู้ทดสอบ — ถ้าตัวอย่างไม่ครบ 5 คนที่ไม่เคยใช้แชท ผลทดสอบใช้ไม่ได้และต้องจัดผู้ทดสอบใหม่
- TC เดิมที่ซ้ำกัน (TC-CHAT-01-4 ซ้ำ TC-CHAT-07-1, TC-CHAT-07-3 ซ้ำ TC-CHAT-07A-1, TC-CHAT-07A-4 ซ้ำ TC-CHAT-07-1, TC-CHAT-03D-3 ซ้ำ TC-CHAT-03C-2, TC-CHAT-03-2 เดิมซ้ำ TC-CHAT-03-1, TC-CHAT-03A-2 เดิมซ้ำ TC-CHAT-03A-1, TC-CHAT-02B-2 เดิมซ้ำ TC-CHAT-02B-1): รวมหรือแทนที่ด้วยกรณีที่ต่างกันจริง
- การลองซ้ำอัตโนมัติ (FR-CHAT-14) ทำฝั่ง Frontend → TC-CHAT-04A-* ตรวจด้วย vitest เท่านั้น (TC เดิมระบุ pytest ซึ่งไม่มี Backend retry ให้ทดสอบ)
- spec ไม่กำหนดช่วงเวลาห่างของ retry จึงไม่มี TC ตรวจ backoff
