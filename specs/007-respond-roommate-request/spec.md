# Feature: รับ/ปฏิเสธคำขอเป็นเมท (Respond to Roommate Request)
Spec ID: SPEC-SRR-007 | Source: SRS ข้อ ... (FR-SRR) | Use case: UC-07
Owner: ทีม vista and friend | Status: Draft v2 | Updated: 2569-09-20

## Goal
นักศึกษาสามารถตอบรับหรือปฏิเสธคำขอเป็นเมทที่ได้รับ
และระบบสามารถปรับปรุงสถานะคำขอพร้อมแจ้งผลให้อีกฝ่ายทราบได้

## Scope
### In scope
- เปิดหน้าคำขอเป็นเมท
- แสดงรายละเอียดของผู้ส่งคำขอ
- เลือกยอมรับหรือปฏิเสธคำขอ
- บันทึกผลการตอบรับ
- ปรับปรุงสถานะคำขอ
- แจ้งผลให้อีกฝ่ายทราบ

### Out of scope
- การส่งคำขอเป็นเมท (UC-06)
- การสร้างโปรไฟล์หาเมท (UC-01)
- การแก้ไขโปรไฟล์หาเมท (UC-02)
- การค้นหาเมท (UC-04)
- การติดต่อหรือแชทกับรูมเมท

## Constraints
- CON-SRR-01 นักศึกษาต้องเข้าสู่ระบบก่อนจึงสามารถจัดการคำขอเป็นเมทได้
- CON-SRR-02 นักศึกษาต้องมีคำขอเป็นเมทที่รอการตอบรับจึงสามารถตอบครั้งแรกได้ และต้องเป็นผู้รับคำขอจึงสามารถเปลี่ยนผลการตอบรับภายหลังได้
- CON-SRR-03 ระบบต้องแสดงรายละเอียดของผู้ส่งคำขอก่อนที่นักศึกษาจะตอบรับหรือปฏิเสธ
- CON-SRR-04 ระบบต้องปรับปรุงสถานะคำขอตามผลการตอบรับ
- CON-SRR-05 หากคำขอถูกยกเลิกไปก่อนแล้ว ระบบต้องไม่อนุญาตให้ดำเนินการกับคำขอดังกล่าว
- CON-SRR-06 เมื่อยอมรับคำขอ คำขออื่นของผู้รับที่ยังรอการตอบรับต้องถูกปฏิเสธโดยอัตโนมัติ
- CON-SRR-07 คำขอที่ผู้ส่งยกเลิกได้ต้องอยู่ในสถานะรอการตอบรับ และคำขอที่ยกเลิกแล้วไม่สามารถตอบรับหรือปฏิเสธได้

## Requirements
- FR-SRR-01 ระบบต้องให้นักศึกษาสามารถเปิดหน้าคำขอเป็นเมทได้
- FR-SRR-02 ระบบต้องแสดงรายละเอียดของผู้ส่งคำขอ
- FR-SRR-03 ระบบต้องให้นักศึกษาสามารถเลือก "ยอมรับ" หรือ "ปฏิเสธ" คำขอได้
- FR-SRR-04 ระบบต้องบันทึกผลการตอบรับของนักศึกษา
- FR-SRR-05 เมื่อยอมรับคำขอ ระบบต้องปรับสถานะคำขอเป็น "จับคู่สำเร็จ"
- FR-SRR-06 เมื่อปฏิเสธคำขอ ระบบต้องปรับสถานะคำขอเป็น "ปฏิเสธ"
- FR-SRR-07 ระบบต้องแจ้งผลการตอบรับให้อีกฝ่ายทราบในระบบและผ่าน push notification
- FR-SRR-08 หากคำขอถูกยกเลิกไปก่อนแล้ว ระบบต้องแจ้งว่าคำขอไม่สามารถดำเนินการต่อได้
- FR-SRR-09 เมื่อยอมรับคำขอ ระบบต้องปฏิเสธคำขออื่นของผู้รับที่ยังรอการตอบรับโดยอัตโนมัติ
- FR-SRR-10 ระบบต้องให้ผู้รับเปลี่ยนผลการตอบรับภายหลังได้ทั้งจากจับคู่สำเร็จเป็นปฏิเสธ และจากปฏิเสธเป็นจับคู่สำเร็จ
- FR-SRR-11 เมื่อมีการเปลี่ยนผลการตอบรับหรือปฏิเสธคำขออื่นโดยอัตโนมัติ ระบบต้องแจ้งเตือนผู้เกี่ยวข้อง
- FR-SRR-12 หากบันทึกผลการตอบรับล้มเหลว ระบบต้องคงสถานะเดิมและให้ลองใหม่
- FR-SRR-13 หากแจ้งเตือนผลการตอบรับล้มเหลว ระบบต้องคงสถานะใหม่และแจ้งว่าไม่สามารถส่งการแจ้งเตือนได้

## Quality Requirements
- NFR-SRR-01 ระบบต้องอนุญาตให้เฉพาะนักศึกษาที่เป็นผู้รับคำขอสามารถตอบรับหรือปฏิเสธคำขอนั้นได้
- NFR-SRR-02 ระบบต้องไม่ปรับปรุงสถานะคำขอ หากคำขอถูกยกเลิกไปก่อนแล้ว
- NFR-SRR-03 ในการทดสอบกับนักศึกษาที่ไม่เคยตอบคำขอ 5 คน อย่างน้อย 80% ต้องตอบรับหรือปฏิเสธสำเร็จโดยไม่รับคำแนะนำ

## Acceptance Criteria
- [ ] AC-SRR-01 (FR-SRR-01, FR-SRR-02)
      Given นักศึกษาเข้าสู่ระบบแล้วและมีคำขอเป็นเมทที่รอการตอบรับ
      When นักศึกษาเปิดหน้าคำขอเป็นเมท
      Then ระบบแสดงรายละเอียดของผู้ส่งคำขอ

- [ ] AC-SRR-02 (FR-SRR-03)
      Given นักศึกษาเปิดรายละเอียดคำขอเป็นเมท
      When นักศึกษาเลือก "ยอมรับ" หรือ "ปฏิเสธ"
      Then ระบบรับผลการตอบรับของนักศึกษา

- [ ] AC-SRR-03 (FR-SRR-04, FR-SRR-05)
      Given นักศึกษาเลือก "ยอมรับ" คำขอ
      When นักศึกษายืนยันการตอบรับ
      Then ระบบบันทึกผลการตอบรับและปรับสถานะคำขอเป็น "จับคู่สำเร็จ"

- [ ] AC-SRR-03A (FR-SRR-09)
      Given ผู้รับมีคำขออื่นที่ยังอยู่ในสถานะ "รอการตอบรับ"
      When ผู้รับยืนยันการตอบรับคำขอหนึ่งรายการ
      Then ระบบปรับคำขอที่เลือกเป็น "จับคู่สำเร็จ" และปรับคำขออื่นของผู้รับเป็น "ปฏิเสธ" โดยอัตโนมัติ

- [ ] AC-SRR-04 (FR-SRR-04, FR-SRR-06)
      Given นักศึกษาเลือก "ปฏิเสธ" คำขอ
      When นักศึกษายืนยันการปฏิเสธ
      Then ระบบบันทึกผลการตอบรับ
      และปรับสถานะคำขอเป็น "ปฏิเสธ"

- [ ] AC-SRR-05 (FR-SRR-07)
      Given นักศึกษาตอบรับหรือปฏิเสธคำขอสำเร็จ
      When ระบบบันทึกผลการตอบรับ
      Then ระบบแจ้งผลให้อีกฝ่ายทราบ

- [ ] AC-SRR-05A (FR-SRR-11)
      Given มีการเปลี่ยนผลการตอบรับหรือมีคำขอถูกปฏิเสธโดยอัตโนมัติ
      When ระบบบันทึกการเปลี่ยนแปลง
      Then ระบบแจ้งเตือนผู้เกี่ยวข้องในระบบและส่ง push notification

- [ ] AC-SRR-06 (FR-SRR-08)
      Given คำขอเป็นเมทถูกยกเลิกไปก่อนแล้ว
      When นักศึกษาพยายามตอบรับหรือปฏิเสธคำขอ
      Then ระบบแจ้งว่าคำขอไม่สามารถดำเนินการต่อได้และไม่ปรับปรุงสถานะคำขอ

- [ ] AC-SRR-07 (NFR-SRR-01)
      Given นักศึกษาเข้าสู่ระบบแล้วแต่ไม่ใช่ผู้รับคำขอ
      When นักศึกษาพยายามตอบรับหรือปฏิเสธคำขอของผู้อื่น
      Then ระบบปฏิเสธการดำเนินการดังกล่าว

- [ ] AC-SRR-08 (FR-SRR-10)
      Given ผู้รับมีคำขอที่ตอบรับหรือปฏิเสธไปแล้ว
      When ผู้รับเปลี่ยนผลการตอบรับ
      Then ระบบบันทึกสถานะใหม่เป็น "จับคู่สำเร็จ" หรือ "ปฏิเสธ" ตามที่เลือก

- [ ] AC-SRR-09 (NFR-SRR-03)
      Given นักศึกษาที่ไม่เคยใช้ฟังก์ชันตอบคำขอจำนวน 5 คน
      When นักศึกษาแต่ละคนตอบรับหรือปฏิเสธคำขอ
      Then อย่างน้อย 4 คนดำเนินการสำเร็จโดยไม่รับคำแนะนำ

- [ ] AC-SRR-10 (FR-SRR-12)
      Given นักศึกษาเลือกผลการตอบรับ
      When การบันทึกผลการตอบรับล้มเหลว
      Then ระบบคงสถานะเดิม แจ้งข้อผิดพลาด และให้นักศึกษาลองใหม่

- [ ] AC-SRR-11 (FR-SRR-13)
      Given ระบบบันทึกผลการตอบรับสำเร็จ
      When การแจ้งเตือนผลการตอบรับล้มเหลว
      Then ระบบคงสถานะใหม่และแจ้งว่าไม่สามารถส่งการแจ้งเตือนได้

## Assumptions & Open Questions
- ASM-SRR-01 นักศึกษาต้องเข้าสู่ระบบก่อนใช้งานฟังก์ชันรับหรือปฏิเสธคำขอ
- ASM-SRR-02 นักศึกษาต้องมีคำขอเป็นเมทที่รอการตอบรับ
- ASM-SRR-03 ระบบสามารถตรวจสอบสถานะของคำขอเป็นเมทได้
- ASM-SRR-04 ระบบมีระบบแจ้งเตือนสำหรับแจ้งผลให้อีกฝ่ายทราบ

- Q-SRR-01 หากยอมรับคำขอแล้ว ระบบต้องสร้างสถานะ "จับคู่สำเร็จ" ทันทีหรือไม่?
-> ตอบแล้ว: จับคู่สำเร็จทันที และปฏิเสธคำขออื่นที่ยังรอการตอบรับโดยอัตโนมัติ
- Q-SRR-02 หลังจากปฏิเสธคำขอ ผู้ส่งสามารถส่งคำขอใหม่ได้หรือไม่?
-> ตอบแล้ว: ส่งคำขอใหม่ไปยังผู้รับคนเดิมได้
- Q-SRR-03 ผู้รับสามารถเปลี่ยนผลการตอบรับภายหลังได้หรือไม่?
-> ตอบแล้ว: เปลี่ยนได้ทั้งจากจับคู่สำเร็จเป็นปฏิเสธ และจากปฏิเสธเป็นจับคู่สำเร็จ
- Q-SRR-04 เมื่อคำขอถูกยกเลิก ใครเป็นผู้ยกเลิกคำขอได้?
-> ตอบแล้ว: ผู้ส่งยกเลิกได้เฉพาะคำขอที่ยังรอการตอบรับ
